# 평가계획 실채움 워크플로 (두뇌 판단 J1~J6)

교수학습운영 및 평가계획(도교육청 양식)은 빈 HWPX 양식 + 검토용 Markdown을 넣으면
`apply_evalplan_fill`이 **한 번에** 바이트 보존 채움본을 만든다. 구조 prune·성취기준·성취율·
반영비율·§7 세부기준·정의적 표·§8 채움 같은 결정론적 작업은 전부 core가 한다.

이 문서는 core가 **의도적으로 하지 않는** 판단을 가르친다. 그 판단은 렉시콘·패턴으로
하드코딩하면 새 양식마다 코드를 고쳐야 하므로(과적합 신호) core에 넣지 않았다. 스킬(LLM)이
자연어 규칙으로 담당한다. 과목·학년별 분기를 코드에 넣지 말고, 아래 판단을 문맥으로 내려라.

## 대표 경로 — clean phase

깨끗한 붙여넣기용 MD를 저작했으면 `phase="clean"` 한 경로로 채움 + 정리까지 끝낸다.

```text
apply_evalplan_fill(
  filename=".../빈양식.hwpx",
  review_md=".../검토용.md",
  output=".../채움본.hwpx",
  phase="clean",            # 채움 + core 결정론적 정리(제목/교사/정의적 채움·지시문 prune·빨강 제거·파랑→검정·캡션 strip)
  render_check="required",  # 실한컴 전 페이지 판정으로 게이트
  score_gold_path=".../gold.hwpx"  # 선택: 같은 계열 승인본이 있으면 정량 비교
)
```

- `phase`는 `structural` | `all`(기본) | `clean`. **`clean`이 제출용 채움본을 한 번에 내는 대표
  경로**다. `all`은 채움만 하고 정리를 안 하므로(옛 동작 보존) 별도 정리 도구를 이어붙여야 한다.
- `phase="clean"`의 정리 리포트는 응답의 `contentReport.finalize`(제목/교사/정의적 채움 여부와
  삭제·캡션 건수)에 실린다. 채움 각 영역 리포트는 `contentReport.schedule/achievement/levels/
  rubrics/ratio/sections`에 실린다.
- 잘못된 `phase` 값은 `EVALPLAN_PHASE_INVALID`로 fail-closed 한다(무음 저하 없음).

## 도구 호출 순서

1. **J1** — 원자료를 core가 파싱하는 **정확한 붙여넣기용 MD**로 저작한다.
2. `apply_evalplan_fill(..., phase="clean", render_check="required")` — 채움 + 정리 + 렌더 게이트.
3. `contentReport` 각 영역 건수와 `renderVerdict`(겹침·오버플로·페이지 경계)를 읽는다(**J6**).
4. 결과를 오너 검수 흐름으로 넘긴다. 기계 PASS를 "완성·제출가능"으로 번역하지 않는다(**J6**).

낯선 양식이면 채움 전에 `scan_form_guidance`로 지시문 후보를, `get_document_map`으로 표·앵커
구조를 bounded로 훑어 J2~J5 판단의 근거를 모아도 된다.

## J1. 깨끗한 붙여넣기용 MD 저작 (상류·최우선)

core는 MD를 **신뢰**한다. 포맷이 어긋나면 해당 영역이 0건으로 채워지고 §가 **무음으로 빈다**.
그러므로 원자료 → 구조화 MD 변환에서 아래 포맷을 정확히 맞춰라.

### 섹션 골격

`# 제목 … 「과목명」 …`(제목), `> 담당교사: 이름`(교사), `## Ⅰ. 교수학습 운영 계획`(운영 표),
`## Ⅱ. 평가 세부 계획` 아래 `### 1.`~`### 11.` 번호 섹션. 섹션 번호·머리말은 양식 관례를 따른다.

### §7 수행평가 세부기준 — 두 포맷 중 하나

**(a) detailed 배점 rubric (현행 평가계획 포맷, 권장).** 수행영역마다 `#### ① 제목 (N점)` H4
헤딩, 영역 메타는 불릿, 세부 영역은 `［세부 영역 가. 이름 (N점)］` 마커 뒤 `평가요소 | 수행수준 |
배점` 표로 쓴다. 한 평가요소의 배점 사다리는 평가요소 셀을 비운 연속 행으로 잇는다.

```text
#### ① 영역 가 (60점)

- **성취기준**: [12합성01-01]
- **수행과제**: (합성 예시) 과제 설명
- **평가 방법**: 관찰·산출물
- **영역 만점**: 60점

［세부 영역 가. 세부이름 (40점)］

| 평가요소 | 수행수준(채점 기준) | 배점 |
|---|---|---|
| 요소1 | 상: 기준 서술 | 20 |
|      | 중: 기준 서술 | 14 |
|      | 하: 기준 서술 | 8 |

［영역 공통］

| 구분 | 채점 기준 | 배점 |
|---|---|---|
| 기본점수 | — | 18 |
```

**(b) legacy 단순 포맷.** `**① 영역 가 (60점)**` + `평가항목 | 채점 기준(배점)` 표. 배점은 셀 안
`완비 **40** / 부분 **20**`처럼 verbatim. 새 저작은 (a)를 쓰되, 원자료가 단순하면 (b)도 채워진다.

**배점·수행수준 문구는 원자료 그대로 옮겨라. 없는 배점을 지어내거나 요약하지 마라.**

### §8 정의적 능력 평가 — 1행 = 1측면

`N적 측면(부연): 설명` 한 줄에 한 측면. core는 이 정규식으로 §8 표 1..3행에 1:1 매핑한다.
형태가 다르면 매핑이 0건이 된다.

```text
### 8. 정의적 능력 평가
- 인지적 측면(합성 예시): 측면 설명 문장.
- 정의적 측면(합성 예시): 측면 설명 문장.
- 실천적 측면(합성 예시): 측면 설명 문장.
```

### 무음 갭 자기점검

채움 뒤 `contentReport`에서 각 영역 건수를 확인한다. `rubrics`가 0건이거나
`finalize.affective_rows`가 0이면 §7/§8 포맷이 어긋났다는 신호다. 빈 채로 넘기지 말고 MD 포맷을
고쳐 다시 채운다. 모호하거나 원자료에 없는 값은 지어내지 말고 `needs_review`로 남긴다.

## J2. 렉시콘 밖 신규 지시문 문구 인식

core의 `guidance_scan.is_form_instruction`은 알려진 한국어 양식 지시 상투구 렉시콘이다. 처음 보는
도너가 낯선 표현("○○을 참고하여 기술하시오" 류)으로 안내하면 렉시콘이 놓친다. 도너의 안내
문단을 읽고 **삭제 대상(양식 스캐폴딩)인지 판정**해, J1의 MD 저작 단계에서 아예 넣지 않거나
`needs_review`로 표시하라. core 정규식에 억지로 문구를 추가하지 마라(과적합 신호).

## J3. 지시문처럼 보이는 정상 본문 구별

"삭제…", "…하지 않는다" 처럼 지시문으로 보이지만 실제로는 정상 규정인 문장이 있다(예: "감점하되
삭제하지 않는다"는 채점 규정). 렉시콘은 이를 오삭제할 수 있다. **문맥으로 정상/지시를 구별**해
보존할 문장을 정하고, 위험하면 채움 전에 오너에게 확인한다. core는 모호 마커(※·유의)는 1차
방어로 제외한다.

## J4. 모호한 정의적 측면 → 셀 매핑 (1:1이 아닐 때)

core는 §8 측면 행을 표 1..3행에 **순서대로** 넣는다(1:1 가정). 측면 수 ≠ 표 행 수이거나, 도너마다
표의 열 의미가 다르면 순서 매핑이 틀린다. **어느 측면이 어느 행/열에 가는지** 판단하고, 1:1이
아니면 MD를 표 순서에 맞게 재배열하거나 오너에게 매핑을 확인한 뒤 채운다.

## J5. band-count 동률 시 성취율 변형 선택

core는 MD의 성취도 단계 수(3단계/5단계)로 유지할 성취율 표를 고른다. 도너가 같은 단계 수의 변형을
여럿 실으면(예: 40% 보장지도 주석 유무) band-count로 갈리지 않는다. 이때 어느 변형이 "우리 것"인지
최종 판단은 스킬 권위다. 제목 「」 안 과목명과 각 변형의 빨강 지시문(예: 특정 과목 한정 주석)을
대조해 옳은 변형을 지정하고, 나머지 변형은 삭제 대상으로 둔다. 근거가 모호하면 오너에게 확인한다.

## J6. 렌더 게이트 결과 해석 → 재작업·검수 판단

`render_check="required"`의 `renderVerdict`와 `verify_form_fill`은 실한컴 렌더로 겹침·오버플로·
페이지 경계를 **계측**한다. 이것은 진단이지 합격 도장이 아니다.

- `renderChecked=false`(오라클 없음)면 완료를 확언하지 않는다. 정직하게 "미검증"으로 보고한다.
- 겹침·오버플로·페이지 증가가 잡히면 원인(과다 텍스트·표 폭·줄겹침)을 짚어 J1 MD 또는 채움을
  고쳐 다시 돌린다.
- **기계 점수·PASS를 "제출 가능/완성/수렴"으로 번역하지 마라.** 최종 판정은 오너 검수다. 루트의
  검증도 스코어러와 독립된 수단(시각 전수)으로 이뤄진다. 스킬은 결과를 오너 검수 흐름으로 넘기고,
  스코어를 근거로 완성을 선언하지 않는다.

## core가 이미 처리 (스킬 불필요)

빨강 지시 run 제거·파랑→검정 재색·placeholder(◯◯◯·(**)) 제거, §4~§5 사이 외래 `(N) 영역`
부헤더, §7~§8 사이 외래 샘플 헤딩, 최소성취수준 고아 블록, 성취수준별 고정분할점수 라벨,
표 꼬리 캡션 strip, 제목/교사/정의적 표 채움. `phase="clean"`이면 위가 전부 자동으로 돈다.

## 상의·검수 규칙

- fill-plan은 항목별 결정표로 오너와 **같이 확정**한다. 방향 승인("해줘")은 계획 승인이 아니다.
  생략은 오너의 명시적 지시가 있을 때만 한다.
- 명확한 매핑은 재질문하지 않는다. 모호·민감·원자료 부재 값은 빈칸 무음 채움 대신 `needs_review`.
- 결과 파일의 `openSafety.ok == true`를 확인하기 전에는 handoff하지 않는다. 원본을 덮어쓰지 않고
  항상 다른 destination에 쓴다. 채움 값에 `<`, `>` 같은 XML 조각을 넣지 않는다.
- facade가 unavailable이면 typed reason과 요구 버전을 보고하고 설치를 교정한다. 새 작업을 수동
  `apply_table_ops` 조합으로 조용히 낮추지 않는다.
