# 공문서 작성규정 lint 규칙 근거

이 문서는 `inspect_official_document_style`이 검사하는 공문서 작성 관행의 근거와
수정 방향을 코드 밖에 고정해 두는 reference다. 기관별 최신 행정업무운영 편람,
행정문서 작성 실무 지침, 내부 문서 서식 기준이 더 엄격하면 그 기준을 우선한다.

## 항목 표시 체계

- 기본 순서는 `1.` -> `가.` -> `1)` -> `가)` -> `(1)` -> `(가)`이다.
- 중간 단계를 건너뛴 항목 표시는 수정한다. 예: `1.` 다음에 바로 `1)`을 쓰지 않는다.
- 부모 단계 없이 하위 단계가 먼저 나오면 상위 항목을 추가하거나 현재 항목 표시를 상위 단계로 올린다.

## 끝 표시

- 본문이 끝나는 위치에는 `끝.` 표시를 둔다.
- 본문 문장 끝에 붙이는 경우 `끝.` 앞에 두 칸을 둔다.
- 붙임 또는 첨부가 있으면 붙임 목록을 먼저 쓰고, 마지막 비어 있지 않은 문단에 `끝.`을 단독으로 둔다.

## 붙임 표시

- 붙임은 문서명과 부수를 함께 적는다.
- 권장 예: `붙임 1. 세부계획서 1부.`
- `붙임: 자료`처럼 콜론만 쓰거나 부수와 마침표가 없는 표기는 수정한다.

## 날짜와 금액

- 날짜는 `2026. 6. 11.`처럼 연, 월, 일 뒤에 마침표와 공백을 둔다.
- `2026-06-11`, `2026/06/11`, `2026.06.11.`처럼 하이픈, 슬래시, 붙은 점, 0 채움 표기는 수정한다.
- 금액은 `1,000,000원`처럼 천 단위 구분을 둔다. 품의서, 예산서, 지급 요청 문서에서는 필요하면 한글 금액도 병기한다.

## 문장부호 간격

- 콜론과 물음표 앞에는 공백을 두지 않는다.
- 예: `제목: 내용`, `참석 여부?`

## 결재란

- builder 경로에서는 `hwpx.approval_box()` 또는 `hwpx.builder.approval_box()`를 사용한다.
- document-plan v2에서는 `{"type": "approval_box"}` block을 사용한다.
- 기본 열은 `기안`, `검토`, `결재`, `전결`이며 내부적으로 서명 영역을 병합 표로 만든다.
